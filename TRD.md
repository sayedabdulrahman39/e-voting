# TRD: Technical Requirements Document

## 1. Architecture

```
Browser (React + Vite)
 ├─ Supabase JS (anon key)  -> Auth (email OTP), DB reads/writes under RLS
 ├─ circomlibjs + snarkjs   -> secret, commitment, Merkle path, Groth16 proof (all local)
 └─ Server API (Express)    -> relayer + admin operations
                                 │ ethers v6 (admin key, relayer key)
                                 ▼
                         EVM chain (Hardhat local -> Sepolia)
                          ├─ VoterRegistry   (root per election, lock)
                          ├─ Voting          (castVote, nullifiers, tally)
                          ├─ Groth16Verifier (generated by snarkjs)
                          └─ ContentAttestation (manifesto hashes)
```

Layers = the "tri-modular" design: **(1) Database/Backend (identity, roles)**,
**(2) ZKP layer (privacy)**, **(3) Blockchain layer (tamper-evidence)**.

## 3. Cryptographic Specification (authoritative)

| Item | Definition |
|---|---|
| Field / curve | BN254 (alt_bn128) |
| Hash in circuit | Poseidon (circomlib) |
| Proof system | Groth16 via snarkjs |
| Tree | Binary Merkle tree, Poseidon(2), **depth 16** (configurable constant), empty leaf = 0 |
| Identity commitment | `commitment = Poseidon(secret)` |
| Nullifier | `nullifier = Poseidon(secret, electionId)` |
| Off-chain content hash | keccak256 of UTF-8 manifesto (normalize: trim, `\r\n` -> `\n`) |

### Circuit `vote.circom`
Private inputs: `secret`, `pathElements[16]`, `pathIndices[16]`
Public inputs: `electionId`, `recipient` (uint160 of relayer address), `candidateId`
Outputs: `merkleRoot`, `nullifier`

Constraints:
1. `leaf = Poseidon(secret)`
2. Merkle path from `leaf` using `pathElements/pathIndices` (each index constrained binary) equals `merkleRoot`
3. `nullifier = Poseidon(secret, electionId)`
4. `recipient` and `candidateId` are included as public inputs and constrained with a dummy square
   (`recipientSq <== recipient * recipient`) so they cannot be optimized away.

**Public signal order MUST be read from the generated `public.json` / `Verifier.sol` and recorded
in `memory.md`.** Expected: `[merkleRoot, nullifier, electionId, recipient, candidateId]`
(outputs first, then public inputs). Do not assume; verify.

### Build pipeline (`circuits/build.sh`)
```
circom vote.circom --r1cs --wasm --sym -o build
snarkjs powersoftau new bn128 14 build/pot14_0.ptau
snarkjs powersoftau contribute build/pot14_0.ptau build/pot14_1.ptau --name="c1" -e="<entropy>"
snarkjs powersoftau prepare phase2 build/pot14_1.ptau build/pot14_final.ptau
snarkjs groth16 setup build/vote.r1cs build/pot14_final.ptau build/c0.zkey
snarkjs zkey contribute build/c0.zkey build/final.zkey --name="c2" -e="<entropy>"
snarkjs zkey export verificationkey build/final.zkey build/vkey.json
snarkjs zkey export solidityverifier build/final.zkey ../contracts/contracts/Groth16Verifier.sol
```
Copy `vote.wasm` and `final.zkey` to `frontend/public/zk/`. Re-run copy + verifier regeneration
**every time the circuit changes** (verifier must match the circuit exactly).
Power of Tau size 14 supports ~16k constraints; bump to 15/16 if constraint count exceeds it.

## 4. Smart Contracts (Solidity ^0.8.20)

### `VoterRegistry.sol` (Ownable)
```
mapping(uint256 => bytes32/uint256) rootOf;  mapping(uint256 => bool) isLocked;
setRoot(uint256 electionId, uint256 root)   onlyOwner, require(!isLocked)
lockRoot(uint256 electionId)                onlyOwner, require(root != 0)
event RootSet, RootLocked
```
### `ContentAttestation.sol` (Ownable)
```
mapping(uint256 candidateId => Attestation{bytes32 hash; uint64 version; uint64 ts;})
attest(uint256 candidateId, bytes32 hash)   onlyOwner, increments version
verify(uint256 candidateId, bytes32 hash) view returns (bool)
event Attested(candidateId, hash, version)
```
### `Voting.sol` (Ownable)
```
enum Status { None, Created, Open, Closed }
createElection(uint256 electionId, uint256[] candidateIds)  onlyOwner; requires registry locked
openElection(id) / closeElection(id)                        onlyOwner
castVote(uint[2] a, uint[2][2] b, uint[2] c, uint[5] pub)   public
tally(uint256 electionId, uint256 candidateId) view returns (uint256)
nullifierUsed(uint256 electionId, uint256 nullifier) view returns (bool)
event VoteCast(uint256 indexed electionId, uint256 indexed nullifier, uint256 candidateId)
```
`castVote` checks, in order:
1. election status == Open
2. `pub.electionId` matches; registry locked and `rootOf(electionId) == pub.merkleRoot`
3. `address(uint160(pub.recipient)) == msg.sender`
4. `candidateId` is registered for the election
5. `!nullifierUsed[electionId][nullifier]`
6. `verifier.verifyProof(a, b, c, pub)` is true
Then set nullifier used, increment tally, emit event. Use custom errors.

### Required tests (min. 15)
valid vote; double vote (same nullifier) rejected; wrong root rejected; tampered proof rejected;
wrong recipient (front-running) rejected; vote before open rejected; vote after close rejected;
unknown candidate rejected; setRoot after lock rejected; non-owner setRoot/lock/open rejected;
createElection without locked root rejected; attest + verify true; verify wrong hash false;
attest by non-owner rejected; re-attest increments version.

## 5. Database (Supabase Postgres)

```sql
create type user_role as enum ('ADMIN','CANDIDATE','VOTER');
create type election_status as enum ('DRAFT','REGISTRATION','LOCKED','OPEN','CLOSED');

create table profiles (
  id uuid primary key references auth.users on delete cascade,
  role user_role not null default 'VOTER',
  full_name text, voter_ref text unique, created_at timestamptz default now()
);
create table elections (
  id bigint generated always as identity primary key,
  title text not null, description text,
  status election_status not null default 'DRAFT',
  merkle_root text, tree_depth int not null default 16,
  starts_at timestamptz, ends_at timestamptz
);
create table candidates (
  id bigint generated always as identity primary key,
  election_id bigint references elections on delete cascade,
  profile_id uuid references profiles,
  display_name text not null, manifesto_text text,
  manifesto_hash text, attest_tx text,
  stance_vector jsonb,            -- 6 numbers, 1..5
  approved boolean default false
);
-- WHO may vote (eligibility), no commitment here
create table voter_eligibility (
  election_id bigint references elections on delete cascade,
  user_id uuid references profiles on delete cascade,
  eligible boolean default false, commitment_submitted boolean default false,
  primary key (election_id, user_id)
);
-- PUBLIC commitments, deliberately NO user_id column
create table voter_commitments (
  election_id bigint references elections on delete cascade,
  commitment text not null, leaf_index int not null,
  primary key (election_id, commitment)
);
create table audit_log (
  id bigint generated always as identity primary key,
  election_id bigint, stage text not null, tx_hash text, created_at timestamptz default now()
);
```
**Privacy rule:** never join commitments to users; never store nullifiers, vote choices, IPs, or
wallet addresses in Supabase.

### RLS policy summary
- `profiles`: user reads own row; ADMIN reads all; role can only be changed by service role.
- `elections`, `candidates` (approved only), `voter_commitments`: public SELECT; writes via server/ADMIN.
- `candidates`: CANDIDATE can insert/update own row (update sets `approved=false`).
- `voter_eligibility`: user reads own; ADMIN full access.
- `audit_log`: ADMIN SELECT only; inserts by service role.
- Use a `security definer` helper `is_admin()` to avoid recursive policies.

## 6. Server API (Express + TypeScript)
Auth: verify the Supabase JWT (`Authorization: Bearer`) and load role from `profiles`.

| Method / path | Auth | Purpose |
|---|---|---|
| `POST /api/vote` | **none** (proof is auth) | Validate shape, locally `snarkjs.verify`, then relayer calls `castVote`; returns `{txHash, nullifier}`. Rate-limited. No auth/IP logging with nullifier |
| `POST /api/elections/:id/commitments` | VOTER (eligible) | Insert a commitment (dedupe per user via `voter_eligibility.commitment_submitted`, do not store link) |
| `GET /api/elections/:id/commitments` | public after lock | Full ordered commitment list (client builds tree + path) |
| `POST /api/admin/elections/:id/publish-root` | ADMIN | Build Poseidon tree from commitments, `setRoot`, `lockRoot`, save root, audit log |
| `POST /api/admin/elections/:id/open` / `close` | ADMIN | Calls `Voting.openElection/closeElection` |
| `POST /api/admin/candidates/:id/approve` | ADMIN | Compute keccak256, `attest`, store hash + tx |
| `GET /api/health` | none | Health |

Middleware: helmet, CORS allow-list, zod validation, express-rate-limit (stricter on `/api/vote`).
Keys: `ADMIN_PRIVATE_KEY` (owner of contracts), `RELAYER_PRIVATE_KEY` (submits votes), separate wallets.

## 7. Frontend
Routes: `/login`, `/admin/*`, `/candidate/*`, `/voter/*`, `/results`, `/verify`.
Guard by role from `profiles`. Key modules:
- `lib/zk/identity.ts`: generate secret, commitment, IndexedDB store, backup download/restore
- `lib/zk/merkle.ts`: rebuild tree from commitments, produce path
- `lib/zk/prove.ts`: `groth16.fullProve` with progress + timing metrics
- `lib/similarity.ts`: mean-centred cosine similarity (ratings 1-5, subtract 3; guard zero vectors)
- Vote page shows timing breakdown (tree build, proof, relay + confirmation) and the receipt.

## 10. Threat Model (to be expanded in `docs/threat-model.md`)
| Threat | Mitigation | Residual risk |
|---|---|---|
| Double voting | On-chain nullifier set | None if circuit correct |
| Ineligible voter | Merkle membership against locked root | Admin could register fake voters before lock |
| Proof replay / front-running | `recipient` bound to sender | None |
| Vote linked to identity | No wallet/IP/nullifier in DB; client-side path | Relayer sees IP + timing |
| Manifesto tampering | On-chain keccak256 + public recheck | Proves unchanged, not true |
| Key leakage | Keys server-side, `.env`, separate admin/relayer | Operational |
| Lost secret | Mandatory backup | Voter cannot vote |
| Trusted setup compromise | Multi-contribution ceremony | Prototype-grade only |
